# 任务19人工修订演示案验收

本轮基于主分支 `4080c3343cf563b7c5b5323647027375e0353d93`，继续 PR #39。原六份精修稿和追加旅馆稿的首轮审阅见 `2026-11-04-fine-sample-review.md`。本轮从七份原稿中修订三个候选，原稿逐字节保存，修订稿采用独立编号。

## 文件与复现

- `task19-demo/manifest.json` 关联原稿编号、原稿 SHA256、修订稿编号和修订稿 SHA256。
- `task19-demo/originals/` 保存三份原始模型生成稿，均保留 `checked:false`。
- `task19-demo/revised/` 保存人工修订演示案。新增人数清单、签字说明与公交时间记录属于本轮剧情修订，逐项列在下文。
- `task19-demo/*-playthrough.json` 保存最终真实 HTTP 调查的逐步耗时、问话、出示、材料、事件、盲答、提交和结局计数。`attempts/` 保存前次记录及复核结论。
- 本机修订脚本与真实验收脚本位于 `.cache/revise_samples.py`、`.cache/accept_demos.py`。脚本从私有 `.env` 读取密钥，记录不含认证头和密钥。

将修订稿复制到正在运行版本的生成案件目录后即可在目录里开局。网页版目录为 `data/stories/`，桌面默认目录为 `%APPDATA%/KanshanMystery/stories/`。使用了 `KANSHAN_DATA_DIR` 时，将文件复制到该目录下的 `stories/`。三个入口编号分别为 `demo-hotel-revised`、`demo-tide-revised`、`demo-bus-revised`。

## 验收方法

通过正常 `POST /api/games`、`talk`、`show`、`accuse` 路由操作。按预先编排的公开调查路线取证，每个角色至少真实问话一次，再沿证据链拆谎、触发对质和追问最终承认。路线编排使用剧本作者视角，最后答题模型只接收公开调查记录。

两组请求均使用 `deepseek-flash`。SDK 请求钩子逐次核对演员 `thinking=disabled`、编剧 `thinking=enabled`。可解性检查使用原有两次盲答，分别只给汤面、给全部线索。全部材料与公开口供收齐后，另由演员模型根据公开记录选择答案，通过真实接口提交。

每案另穷举256种答案组合，并通过实际接口提交错答。所有结局按引擎首匹配规则计算，完整真相必须仅有全对组合命中。

## 前次发现与复验

- 首次公交修订稿仅看汤面盲答答对3/4，路线通关仍保留该可解性失败。之后调整汤面和题目，并重跑真实完整路线。
