# 2026-11-03 编剧生成耗时对照

## 基线与改动

先读取 `12883e32` 的项目和任务 14，包含 PR 24、25、26 的信任说明、程序硬检查与 JSON 格式恢复。真实测试沿用同一份本机模型配置：演员、编剧均为 `deepseek-flash`。

旧流程每轮生成、审稿分别输出整本 JSON，且各自附一份约 10,697 字符的完整 schema。新流程改为：

1. 编剧生成一次完整剧本，保留思考模式。
2. 先做本地格式、引用、引擎、可达性和数量检查；坏稿携具体问题进入下一轮，跳过审稿与盲答。
3. 合格稿交给关闭思考的审稿调用，只返回 `{"problems":[...]}`，不修改或覆盖剧本。
4. 保留只看汤面、看全部线索的两次盲答检查；硬检查或可解性不通过仍会触发下一轮。

模型请求不再带完整 schema，改为 **2,063 字符**的固定字段契约、条件规则和 JSON 编号关系片段。明确 `knows` 只填 `facts.id`，秘密及 `admit` 必须属于本人 `knows`，公开简介不剧透，对质用角色编号、奖励用线索编号。服务端严格校验保持原样。

未指定规模时优先 3 人、8 线索、2 谎话、3 题、2 结局。三轮上限、600 秒总预算、10 秒保存预留、无效 JSON 重试一次、异常保稿和坏稿不发布均保留。

## 实测方法

在独立进程中直接运行真实 `StudioService._generate`，记录每次逻辑模型调用的角色组、耗时、请求字符数、成功解析结果的重序列化字符数，以及最终质量状态。完成后使用真实 `GameEngine.new_game` 检查能否开局。

计时从生成任务开始，不包含编剧聊天确认、页面操作、角色调查或完整 AI 破案。旧版进程在修改文件前已加载基线代码；每份本机结果记录源文件 SHA-256。原始记录位于 `.cache/writer-speed/<label>/result.json`，步骤日志位于同目录 `steps.log`，不上传密钥、模型正文或生成 YAML。

部分进程并行运行，模型服务耗时存在波动。旧版和新版对同一句话选择了不同默认规模，因此以下是实际样例记录，不能视为等规模的稳定提速率。

## 同一句话医院题材

输入原文：

> 我想玩恐怖一点的，医院题材

| 版本 | 总耗时 | 写稿 / 修订 | 审稿 | 最终规模 | 质量状态 | 能否开局 |
|---|---:|---|---|---|---|---|
| 旧版基线 | 242.69 秒 | 120.12 秒 | 112.00 秒 | 4 人 / 12 线索 / 4 谎话 | checked:true | 是 |
| 优化版初测 | 174.32 秒 | 格式失败 87.71 秒；下一轮 67.88 秒 | 9.09 秒 | 3 人 / 8 线索 / 2 谎话 | checked:false | 是 |
| 最终提示复测 | 160.80 秒 | 70.53 秒；修订 63.70 秒 | 5.25 秒；4.29 秒 | 3 人 / 8 线索 / 2 谎话 | checked:true | 是 |

初测的 87.71 秒包含两次无效 JSON 回复，日志均为语法错误，失败位置分别接近回复末尾。该耗时完整计入总时间，没有扣除重试后只报理想速度。

初测审稿同时包含真实语义弱点、重复意见和机制误判。对照真实 YAML 后，确认“独立证据包含秘密，再向角色出示以解锁”属于正常机制；角色也可以出示其持有记录。随后收紧审稿提示，只报告核对原文后的真实矛盾，合并重复，不凑满条数；原始质量警告和初测记录保留。

最终复测的第一版没有通过全部可解性检查，因此触发第二轮。修订后的审稿和两次盲答均通过，最终才标 `checked:true`。没有为缩短时间跳过检查或清除当前稿的警告。

两次医院对照中，旧审稿输出 8,537 字符；新版初测只输出问题 1,167 字符；最终复测两轮分别为 338、16 字符。旧首轮生成请求为 11,597 字符，最终复测首轮为 2,310 字符。

## 有完整汤面汤底的输入

自拟测试素材：夜班护士收到停用病房的呼叫；原汤底为旧线路串接到资料室、搬档人员误触按钮，床号未随改造更新。按 `seen` 策略改编，保留医院悬疑氛围。

中间优化版本记录：生成 129.54 秒，问题审稿 8.07 秒，两次盲答分别 5.02、3.52 秒；总计 **146.25 秒**。产物为 3 人、8 线索、2 谎话，程序检查通过并能开局，仍有审稿质量警告，保持 `checked:false`。

该样例属于另一种输入，不能与医院一句话样例混合计算成功率或平均提速。

## 剩余问题

- 写稿仍是主要耗时；保留思考模式的完整剧情创作仍需约一分钟或更久，不能承诺秒级完成。
- JSON 语法失败仍会增加一轮的耗时；本次没有观察到长度截断，未猜测性添加输出 token 上限。
- 程序检查、两次盲答和成功开局不等于玩家已完整破案；带警告的样例继续标为未全部通过，剧情体验仍需人工试玩。
- 本次旧版样例约四分钟，没有复现历史记录中接近十分钟的整单超时，不能将本次对照描述成“十分钟降到两分钟”。
