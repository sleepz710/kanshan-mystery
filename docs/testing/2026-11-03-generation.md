## 第一次：复现失败

| 步骤 | 结果 |
|---|---|
| 新建自己玩剧场 | HTTP 201 |
| 提交素材 | HTTP 200，36.30 秒，直接进入生成 |
| 生成/审稿 | 三轮修订仍未通过程序检查 |
| 总耗时 | 457.95 秒 |
| 最终状态 | failed；无 story_id、无假开局链接；私有草稿保留 |

真实错误是 `events.confront` 写了 `[c2,c3]` 等线索编号，此处必须是两名角色的编号。线索实际存在，旧报错只说“编号不存在”，遗漏了“需要角色编号”，导致修订模型反复修错方向。

修复了以下问题：

1. 条件 schema 明确字段与类型，事件要求 `to`，提示只接受全局完成条件，结局条件互斥；检查器与引擎协议对齐。
2. 角色、线索、事实、事件的引用明确类别。真实错误现在会指出：`事件 ev_lin_clear.confront[0] 须引用 characters.id，c2 属于 clues.id`。不猜测或自动替换剧情中的对质者。
3. 初稿先做本地检查，修订模型收到具体错误和分类编号表。发布版本必须可被引擎读取、线索可达、数量符合系统范围；坏稿保存在私有 `data/drafts/`。
4. 后续坏输出、模型异常或超时，不覆盖或丢弃更早可运行的候选；候选及其检查结果保持对应。
5. 否定句或素材中的“开始生成”不再强制启动。已有素材后的精确确认和策略按钮直接启动，省去重复的模型判意调用。
