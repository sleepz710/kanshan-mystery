## 比较标准

评分表决定取舍(详见 `assignment.md`):

- **技术实现 40%**:功能完整、运行稳定;「算法正确性」要拿得出证据,最好有测试集、能报准确率或召回率。
- **创意与价值 30%**:讲得清用户是谁、他们现在怎么解决、我们好在哪。
- **用户体验 30%**:一条主流程,互评的同学 3 分钟内能自己走完。

加上我们自己的条件:时间一个月左右,靠 vibe coding,每人 AI 额度有限。题目要能拆成几块互不干扰的模块,模块之间用 JSON 约定接口,各自开发。

## A 年报变化雷达(金融 × 科研)

输入股票代码,自动对比这家公司今年和去年的年报,只把「改了什么」挑出来解释,每一条都能点回原文页码。

- **用户与痛点**:散户、金融和会计专业的学生、做公司研究的人。A 股年报动辄两百页,大部分段落年年照抄,要紧的变化(新增风险、业务表述改了、措辞变软、会计政策变更)埋在里面。
- **主流程**
  1. 输入代码和年份,从巨潮资讯网下载两年的年报 PDF。
  2. 按「第 X 节」切章节,两年文本做段落级对齐,标出新增、删除、改写。
  3. 大模型只对改动的段落写一句解读,附两年原文和页码。
  4. 财务信号用代码计算(数据取自 akshare 的结构化报表):应收增速与营收增速、经营现金流与净利润、存货、商誉等,异常的标红。
  5. 结果页:左右对照的高亮视图,旁边一列变化卡片。
- **技术亮点**:长 PDF 解析和章节对齐;语义对齐加文本 diff;数字全部由代码计算并能溯源。
- **正确性**:在真实年报里注入已知改动(增删改段落、改数字),测检出率;再人工标注几家公司的真实变化做抽查。
- **科研延伸**:Lazy Prices(Cohen, Malloy & Nguyen, *Journal of Finance*, 2020)发现美股定期报告文本改动大的公司,后续股票收益偏低。可以拿我们算出的「变化度」在一批 A 股上做个小验证,放进答辩。
- **多语种延伸**:A+H 或海外上市的公司,对比它给境内外投资者的中英文披露是否一致,呼应比赛的「跨语种观点比对」。
- **数据**:巨潮资讯网的年报 PDF(公开);akshare 的 A 股财务数据(免费,不需要 token)。
- **风险与对策**:PDF 里的表格难解析,MVP 只比文字章节,数字走 akshare;年报长、调用贵,只对改动段落调用大模型;现场演示用提前缓存好的公司,不临场下载。
- **模块**:年报下载 / PDF 切章节 / 对齐与 diff / 财务信号 / 解读生成 / 前端 / 评测集。

## B 资产截图体检(金融)

把银行、支付宝、基金、券商 App 的资产页截图丢进来,生成一张个人资产全景图和一份体检报告。比赛例题「个人理财与资产梳理智能体」的一种具体做法。

- **用户与痛点**:刚开始理财的学生和年轻人,钱散在五六个 App 里,说不清总共有多少、风险集中在哪。帮父母梳理家庭资产是同一个场景。
- **主流程**:上传截图 → 多模态模型识别出产品、金额、类型 → 用户确认或修改 → 代码计算总额、配置比例、集中度、流动性 → 生成体检报告(解释现状和常识,不推荐具体产品)。
- **技术亮点**:多模态抽取加人工确认环节;金额汇总由代码完成;截图只在内存里处理、不落盘。
- **正确性**:收集 30–50 张不同 App 的截图(组员自己的,打码后用),标注真值,报字段级准确率。
- **风险与对策**:各 App 截图版式不同,识别会出错,所以确认和修改界面是必做项;同类记账产品多,卖点放在「截图即梳理」和体检解读上。
- **模块**:截图识别 / 数据模型与汇总 / 体检规则与解读 / 前端 / 评测集。

## C 中英文献观点对照(科研)

输入一个研究问题,把中文文献和英文文献各自的结论、方法、证据抽出来,做成观点对照表,看两边哪里一致、哪里分歧。对应比赛例题「跨语种观点比对」「多语种文献摘要」。

- **用户与痛点**:写综述、开题的本科生和研究生。中英文文献常是两个圈子,很难一眼看清两边各怎么说。
- **主流程**:输入问题 → 英文文献从 OpenAlex、Semantic Scholar、arXiv 检索;中文文献由用户上传自己从知网下载的 PDF → 每篇抽取「问题—方法—结论—证据」→ 跨语言聚类成观点 → 对照表加观点地图,每条观点能点回原文段落。
- **技术亮点**:跨语言检索与向量对齐、结构化抽取、观点聚类,四个候选里技术难度最高。
- **正确性**:需要人工标注一批文献的观点归类,工作量大。
- **风险与对策**:知网没有免费的检索接口,中文语料靠用户上传,演示前要自己备好;观点抽取的质量难量化。
- **模块**:英文检索 / PDF 解析 / 观点抽取 / 聚类对齐 / 可视化前端 / 评测集。

## D 论文引用核查(科研)

上传论文或毕业设计,逐条核对参考文献是否真实存在、作者年份刊名对不对、被引文献是否真的支撑引用它的那句话,顺带按国标检查格式。

- **用户与痛点**:所有写论文的学生,互评的同学人人用得上。大模型会编造参考文献:ICLR 2026 对查实含虚构参考文献的投稿一律拒稿;GPTZero 在 NeurIPS 2025 的已录用论文里查出约 100 条虚构引用。学校的查重不查这一项。
- **主流程**:上传 docx、PDF 或 .bib → 解析参考文献和正文引用句 → 去 Crossref、OpenAlex、Semantic Scholar、arXiv 核验 → 每条给出「已核实 / 信息有出入 / 查不到」→ 引用句和被引文献摘要做支撑判断 → GB/T 7714—2025 格式检查 → 在原文位置标注的报告页。
- **技术亮点**:多源核验与模糊匹配;大模型判断「是否支撑」。
- **正确性**:四个里最好做:拿真实论文混入大模型编造的假文献,直接报精确率和召回率。
- **风险与对策**:英文论文已经有不少开源工具(refproof、bibguard、HaRC 等),差异要做在中文场景:docx 毕业论文、中英混排的参考文献、新国标、「是否支撑原句」。中文文献的核验数据源有限,查不到的标「无法核验」,不判定为假。
- **模块**:文档解析 / 多源核验 / 支撑判断 / 格式检查 / 报告前端 / 评测集。

## 考虑过、没放进候选

- **外贸询盘解析**:比赛原例题,撞题概率高;我们也没有真实询盘数据。
- **多语种文献摘要助手**:Kimi、知网研学等产品已经在做,创新分难拿。
- **多 agent 炒股、荐股**:GitHub 上最拥挤的方向(TradingAgents 一类);大模型训练数据里有历史行情和新闻,回测容易虚高;还有投资建议的合规问题。

## 推荐

**首选 A 年报变化雷达**

- 同时落在金融和科研两边;Lazy Prices 这篇论文能直接回答「这个东西有什么价值」。
- 演示直观:左右对照高亮加变化卡片,打开就懂。
- 技术难度够,正确性能用注入改动的测试集量化,正好对上技术分里的「算法正确性」。
- 七个模块边界清楚,适合多人、多个 AI 账号并行。
- 风险集中在 PDF 解析,MVP 绕开表格就能控制住。

**求稳选 D 论文引用核查**:实现最简单、评测最好做、互评同学最有共鸣;创意分要靠中文场景拉开差距。
